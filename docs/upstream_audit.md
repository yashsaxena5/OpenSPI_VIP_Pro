## SPI RTL candidate

- `rtl/` contains `spi_master`, `spi_slave` and `spi_top`. The master implements a synchronous FSM, one active-low CS, fixed elaboration width and divider, full-duplex data, mode and bit-order latches, BUSY and a DONE pulse. The slave oversamples external SPI pins in the system clock domain. `spi_top` connects master and slave for loopback.
- `tb/` contains the three self-checking suites. `assertions/` has instantiated immediate checkers for pin and status invariants. `make sim` runs only `tb_spi_top`. The standalone benches provide independent SPI peers and checks for all four modes, both bit orders, directed patterns, consecutive transfers and random data. The master tests a configuration change mid-frame. The slave tests an early CS release and a CS glitch. Top uses width 8 and divider 8. The master bench uses width 8 and divider 4. Each standalone bench has 10,000 random iterations, and the loopback has 1,000. Bench counters count individual checks. The standard runs leave wider or narrower configurations unqualified.
- `scripts/`, `constraints/` and `reports/` contain Yosys flows, a Sky130 HDLL mapping script, OpenSTA scripts/SDC and upstream reports. Sky130 and OpenSTA depend on the fixed Liberty path and tool. The baseline independently runs Icarus and generic Yosys. Upstream timing and coverage claims were outside the measured baseline.
- Icarus passes the three original benches. A separate Icarus probe at width 1 fails elaboration because the RX concatenations use invalid part selects. Strict Verilator lint reports counter width expansions. Version 5.032 also reports a combinational scheduling warning through the slave's `sample_edge` and `final_edge` assignments. Preserve the original tests, size terminal counts explicitly, and separate edge decode from the FSM when adapting the host. Wishbone CSRs, runtime divider, multiple CS outputs, reset-abort contract and sticky status need project implementation.

## SPI and UART UVM VIP candidate

- `spi_vip/` supplies transaction/configuration classes, `spi_if`, active master and slave drivers, passive monitor, sequencer, callbacks, sequence library and covergroups including mode × width. Configuration advertises all four modes, optional bit order, selectable CS lines/polarity and lengths up to `SPI_MAX_WIDTH` (32). `uart_vip/` has analogous UART components and a UART core example. Neither UART RTL nor UART VIP is needed here.
- `spi_vip/example/` connects two VIP agents and checks reconstructed wire data against drive intent through callbacks. The default test exercises one configured mode with 20 eight-bit words. Sweeping modes requires configuration changes. `example_real_dut/` checks both data directions with a fixed Mode 0, eight-bit `spi_slave_core`, a parallel-data BFM and a Questa `.do` file. Upstream reports QuestaSim 2025.2 with UVM 1.2 and 20/20 real-DUT checks passing. These results remain upstream claims. The real-DUT example exercises the VIP master role. The loopback is the relevant starting point for qualifying the slave role.
- No Wishbone agent, SVA, RAL or systematic negative suite is provided. The monitor frames on CS transitions and assumes one selected target. The slave driver waits for each SCLK edge for the requested width, so reset or premature CS can leave it waiting. The loopback failure condition checks the error count and does not enforce a minimum number of observed items. Require counts, timeouts and an independent peer for qualification.
- The unchanged Mode 0 loopback elaborated and built on Verilator 5.054 with UVM 2020.3.1. Seed 1 reached all 20 checker outcomes and failed all 20, with 29 UVM errors and process exit 0. The first MOSI mismatch compares `0x70913c07` with `0x07`. The checker queues full-width randomized data while the driver transmits the low eight bits, which explains that mismatch. The slave sequence also randomizes its response width over 1–32 bits while the master fixes its width at eight. This can leave the slave waiting across frames and is consistent with the empty expectation queues. Align frame widths and compare only wire-visible bits in isolated qualification before assessing scheduling or attributing failures to the simulator.
- The default loopback exercises callbacks, variable CS events and `fork/join_any` paths. Passing elaboration leaves runtime behavior unqualified. Probe CS aborts, high-impedance MISO behavior, and reachable covergroup bins separately. The upstream Questa real-DUT result is a separate test and was not reproduced here. [Local evidence and reproduction](../reports/baseline/README.md)

## Antmicro UVM compatibility example

- Root files hold `sig_if`, an item, two agent instances, driver, sequencer, monitor, environment, scoreboard and `sig_model_test`. `tb.sv` loops generated signal pulses back through a shared interface. There is no SPI, Wishbone, synthesizable DUT or coverage collector. The test sends ten sequence items and compares monitored pulse lengths through TLM analysis FIFOs.
- The README and its `tuttest`-driven CI use a source build of Verilator, a C++ toolchain, Z3 for constraint solving, and Accellera UVM 2020.3.1 with `UVM_NO_DPI`. Phase 1 locks the matching Accellera Git release `78c06547a2a0a29b3dc9dcafae62b75b2ff61544`. It enables assertions explicitly and requires ten comparison lines plus a zero-error and zero-fatal report. This matters because the upstream `.size()` comparison is FIFO capacity, and an empty FIFO can otherwise produce a vacuous green result. The separate baseline report records the 5.032 compiler failure and the newer build result. [Accellera UVM release](https://github.com/accellera-official/uvm-core/tree/78c06547a2a0a29b3dc9dcafae62b75b2ff61544)

## Wishbone infrastructure reference

- `rtl/` has parameterized arbiter and priority encoder, AXI-Stream-to-Wishbone master, width adapter, async bridge, RAM/dual-port RAM, bus register and mux/arbiter generators. It addresses bus infrastructure rather than a SPI register contract. `tb/wb.py` models master/slave traffic in MyHDL. Pairs of Verilog wrappers and Python tests cover adapters, bridge, mux, RAM, arbitration and AXI-Stream translation. Assertions in the Python tests check readback, lane and operation behavior.
- Legacy Travis CI installs Icarus and MyHDL plus its `myhdl.vpi`, uses Python 3.6 and runs `py.test`. No synthesis flow or verified results were found in the inspected tree. Individual plain-Verilog modules are plausible Verilator inputs. The original MyHDL/Icarus VPI tests require simulator integration work to move. None were executed for this audit. The bus contract for the project comes from B4 Classic. [Wishbone B4 specification](https://cdn.opencores.org/downloads/wbspec_b4.pdf)

## OpenTitan reference

- Audited `hw/ip/spi_host`, `hw/ip/spi_device`, and `hw/dv/sv/spi_agent`. Host RTL includes top-level, FSM, shift register, core, command queue, data formatting, TX/RX FIFOs and generated register packages. It supports multi-CS, programmable SPI mode/clock, standard/dual/quad flash operations, interrupts and passthrough. Device RTL includes command parsing, serializers, SRAM buffering, flash/TPM and passthrough logic. Its bus register interfaces use TL-UL.
- The SPI agent supplies active host/device drivers, passive monitor, configuration, sequencer, sequences and coverage. The host DV tree adds a virtual sequencer, TL-UL agent, RAL generation, pin and bus scoreboard checking, bind files and HJSON testplans. Tests include smoke, data transfer, FIFO error, divider, timing, reset, passthrough and stress. Device DV adds flash, TPM and security testpoints. Dashboards describe upstream runs, while the audited revision was inspected statically here.
- The host `.core` pulls in TL-UL, primitives and project packages and includes a dedicated Verilator lint waiver fileset. DV needs OpenTitan shared UVM libraries, FuseSoC/RAL generation and DVSim. The host simulation configuration names Xcelium and has Xcelium coverage exclusions. Standalone Verilator qualification of that UVM bench would be a separate porting effort. The architecture and testplan patterns are useful at far lower cost than importing the design or agent.

## Paper

The paper describes a Wishbone-compliant SPI master with a Wishbone BFM, an SPI slave, constrained-random UVM sequences, monitor/scoreboard and assertions. It reports QuestaSim simulations and 92.31% coverage from IMC. The article has diagrams and descriptions without a pinned runnable source tree or a Verilator recipe. Use it to inform stimulus and checking boundaries. Keep the predictor separate from the monitor to improve independence. The paper's distribution license does not grant a software reuse license for the design or VIP it describes.

## Reuse obligations and selection

MIT redistribution carries the upstream copyright and license text. Apache-2.0 redistribution carries the license, applicable attribution and any applicable NOTICE, and marks changed files. Apache-2.0 also includes its express patent grant and patent-termination terms. Review source-level and vendor notices at any later import. The phase uses Apache-2.0 for original work and retains upstream license texts in the runtime checkouts. It includes no imported upstream RTL or VIP in the local Git tree. [Third-party notices](../THIRD_PARTY_NOTICES)

Use the small SPI master as a starting point with an independent pin-level qualification gate. The SPI-UART candidate offers a much smaller path to a reusable SPI responder and monitor than OpenTitan's SoC libraries. Keep that choice conditional on the standalone Verilator qualification. Use a project-specific Wishbone slave and agent and draw on OpenTitan for verification structure.
